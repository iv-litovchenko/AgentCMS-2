Задача номер 1. Docker и символические ссылки.

Два разных случая. Первый — симлинк внутри уже собранного контейнера. Просто работает, ничего делать не надо. Второй — сборка образа. Там Docker копирует только то, что лежит прямо в контексте, то есть в папке с docker-compose. Если симлинк торчит наружу, COPY его проигнорирует. Решение: в docker-compose.yml добавь volume, например Desktop в apps/cms/public/files, и тогда папка с Мака появится в контейнере как обычная директория.

Дополнительно: симлинк, который ведёт на путь вне контекста сборки, Docker не увидит. Внутри контейнера симлинки работают как обычно, на Linux. На Docker Desktop весь диск Мака доступен через монтирование тома. Но при сборке образа COPY не пойдёт по симлинку за контекст, поэтому для билда надёжнее копировать напрямую или использовать .dockerignore с исключениями. Если симлинк выходит за другую папку на Mac (например, на Desktop или Downloads), Docker его не увидит при сборке — сослаться напрямую нельзя, только через volume.

Задача номер 2. YAML и schema-driven формы.

Прямо в Symfony из коробки форм на YAML нет. Но есть подход schema-driven: описываешь поля в YAML или JSON, а код строит FormType динамически. В Symfony так не из коробки, но написать свой билдер из YAML-схемы — реально, и для админок это частый паттерн.

YAML в целом: конфиги, docker-compose, Kubernetes, CI-пайплайны — главная территория YAML. Для фронтенда на YAML напрямую ничего нет, но схемы данных и форм через YAML — рабочий вариант.

Задача номер 3: Voxel обсудить.

Voxel заметок: сканер Markdown с YAML-фронтматтером, сервис чтения и записи, MCP-тулы для поиска и правок.

Voxel памяти: внешняя редактируемая база с фильтром на запись (то, что обсуждали в начале).

Voxel файлов: работа с томами и загрузками.

Задача номер 4 (обсудить). Как оцифровать всю жизнь — второй цифровой мозг.

Три слоя: 1) Захват — всё, что делаешь, должно автоматически попадать в систему: выгрузки из приложений, скрипты, импорт почты и календаря. 2) Нормализация — приводишь разнородные данные к единому формату, YAML или структурированные заметки. 3) Доступ — MCP-слой, чтобы и ты, и агент могли читать и править.

Что оцифровывать: пароли — в менеджер с экспортом, документы — сканы в медиатеку, тренировки и английский — регулярные записи с датой.

Подходы в мире: Obsidian, Logseq, Notion — персональные базы знаний. Метод PARA Тиаго Форте: проекты, области, ресурсы, архив. Zettelkasten — карточки со связями между идеями. Workspace как раз ложится в эту парадигму: каждый workspace — отдельная область жизни, внутри YAML-файлы как карточки.

Секрет не в том, чтобы всё записать сразу, а в том, чтобы был поток: каждый день по чуть-чуть.

Главная идея: всё живёт не в разных приложениях, а в одном месте, как в Notion.

Задача номер 5 (обсудить). Нормализация данных.

Нормализация — это перевод чужого формата в свой. Допустим, Strava отдаёт джейсон на пятьдесят полей. Ты не хранишь его как есть. Ты пишешь маленький скрипт, который из этого джейсона вытаскивает четыре вещи: дату, тип активности, длительность, пульс. И записывает их в твой YAML по строгому шаблону. Другое приложение, другой формат — тот же шаблон на выходе. В итоге у тебя все данные в одном виде, и искать по ним можно одинаково.
